## Recording notes
- Start the server clean (`cd backend && node server.js`, `DEMO_MODE` default), so the audit chain and approval queue start empty; no LLM key set, so the planner shows *deterministic*.
- Recorded with Playwright `recordVideo` at 1920×930 (a 150 px caption bar is added below for 1920×1080), a yellow cursor dot and yellow highlight outlines injected for the viewer, and toasts raised above the copilot button. These are recording overlays only; the app code is unchanged.
- Payment step: focus the *Re-type amount* and *6-digit code* fields with the keyboard (Tab), not the mouse — see the known UI issue below.

## Known UI issues found while recording
1. Clicking anywhere inside an approval card (including into the *6-digit code* field, or on *Preview email*) re-renders the Waiting-for-you lane: `#approvals.onclick` in `frontend/sme.js` falls through to `loadApprovals()` when the click is not on a button. A mouse user who types the amount and then clicks the code field loses the typed amount, so Confirm always fails with *Amount does not match*. Not fixed here (the video works around it by focusing fields without clicking).
2. Approving one of the plan's reminders makes the cockpit runway disagree with the headline numbers. After the INV-ANA-0020 reminder executes, the plan shows *2 reminders + ₹9,00,000 loan* and *Lowest point if you approve* drops to about ₹2.6 lakh, *still below buffer*, and the hero changes to "The plan helps, but cash still dips below the buffer". The executed reminder's expected collection seems to be dropped from the plan without being added to the forecast. The video does not click Approve on the reminder, so ₹4,25,618 stays on screen throughout.
3. Cosmetic: the Financing match amount (900000) carries over when you switch to another business (seen on PixelForge).
