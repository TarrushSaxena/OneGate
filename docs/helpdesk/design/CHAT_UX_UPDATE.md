# Chat workspace update

## Reply-target enforcement

Assignment cards use a distinct blue/lavender surface. Connection copy describes whether the specialist has a live OneGate session, without combining the contradictory-looking saved availability and connection labels. Countdown starts immediately and uses the persisted end of the estimated reply range; it updates every second and survives reload. The information control reveals its explanation on hover or keyboard focus.

A durable five-second backend worker escalates missed reply targets once per deadline/version and catches up after restart. The rule is no substantive staff reply before the target—not simply whether their browser is connected. Available seniors are assigned; otherwise the same request remains in a senior queue. Further missed windows route upward through senior support to the department lead; a missed lead target flags leadership review. Waiting-on-user, resolved and self-service records are excluded; staff replies stop the countdown and employee follow-ups start a new reply target. Tests exercise concurrent sweeps, skipped records, senior assignment, no-senior queueing and lead escalation. PostgreSQL acceptance and multi-process event delivery are still unverified.

Implemented light liquid-glass workspace, independently scrolling sidebar/content/chat areas, dynamic viewport sizing, full-width Ask OneGate, sidebar Active/Resolved requests, contextual suggestion chips, optimistic Sending and recoverable Retry states, bounded thinking copy, accessible specialist-confirmation and lifecycle dialogs, routing cards, timelines, resolution summaries and periodically updated estimate ranges plus clock times.

The specialist CTA appears after a saved user message. Clicking it asks the existing backend department model to route the latest message automatically; there is no initial department picker. DistilBERT is attempted first, with the existing local Naive Bayes classifier as fallback. Client-supplied department values are not authoritative. Existing tickets are reused. A small “Wrong team?” action allows an explicit correction with a reason: the same ticket/reference/transcript is retained, the old assignment is released, eligibility/ETA are recomputed, a correction is recorded, and both old and new queues receive invalidation. Resolved requests cannot be rerouted without reopening. Specialist status distinguishes configured availability from an actual connected browser. Authorized typing events expire after inactivity and never trust a submitted employee/user identity. Making a specialist available drains eligible queued requests transactionally and publishes the assignment afterward.

Visual state system: violet thinking/self-service, blue routing/correction, amber assigning/queue, teal assigned/delivery, orange escalation/waiting, green resolution. Each state also has an explicit label/icon. Gradient thinking surfaces, restrained hover lift/reflection and reduced-motion alternatives follow [NN/g visibility-of-status guidance](https://www.nngroup.com/articles/visibility-system-status/) and [Carbon status indicators](https://www.carbondesignsystem.com/building-blocks/core/patterns/status-indicators). No fabricated percentage or artificial delay is added to fast assignments.

Verification: two targeted backend test groups pass, including duplicate handoff, ETA format, assignment-scoped typing and availability-triggered queue assignment. Browser checked policy answering, thinking display, saved history, specialist confirmation and generated request card. At 390 × 844 the composer was inside the viewport and document width was 390 pixels (no page-wide horizontal overflow). The mobile navigation itself scrolls horizontally. Desktop workspace checked at the browser's default size. This is not a complete all-role or all-13-state acceptance report; remaining production-pilot blockers in PILOT_IMPLEMENTATION_STATUS.md still apply.
